# 当前项目可复用的前端 UI 规则

本文档从当前项目已经满意和已经统一过的页面中提炼规则，用于后续新项目或前端 2.0 重建时复用。它不是当前代码的逐行说明，而是把已经验证过的视觉、交互和工程约束整理成可执行规范。

## 适用范围

适用于自动化测试平台类后台系统，包括：

- 系统设置
- 配置中心
- 用例中心
- 缺陷管理
- 接口自动化
- AI 连接、AI 配置、AI 生成记录

后续如果使用 Arco Design Vue，也可以沿用这些规则，只需要把底层组件从 Element Plus 映射到 Arco。

## 当前视觉基准

当前项目中最适合作为样板的页面：

- 系统设置：左侧设置分类 + 右侧内容区。
- 配置中心：左侧配置分类 + 右侧卡片化内容。
- 接口自动化执行 tab：工具型工作台布局。
- 用例中心 AI 配置：双角色模型配置卡片。

新页面应优先向这些页面靠齐，而不是向旧版普通表格后台靠齐。

## 设计 Token

### 字体

默认字体：

```css
font-family: Inter, "PingFang SC", "Microsoft YaHei", sans-serif;
```

规则：

- 正文默认 `14px`。
- 辅助文本默认 `12px`。
- 页面内卡片标题多用 `14px-18px`，不要滥用大标题。
- 行高保持舒展：`12px -> 16px`，`14px -> 20px`，`16px -> 24px`。

### 主色

```css
--app-primary: #2563eb;
--app-primary-hover: #1d4ed8;
--app-primary-active: #1e40af;
```

规则：

- 主操作按钮使用蓝色。
- 链接、激活 tab、当前导航项使用主色。
- 页面不要大面积铺蓝，只在操作、激活、强调处使用。

### 语义色

```css
--app-success: #16a34a;
--app-warning: #ea580c;
--app-danger: #ef4444;
--app-purple: #9333ea;
```

对应规则：

- 成功、通过、已连接：绿色。
- 警告、待确认、建议优化：橙色。
- 失败、删除、异常：红色。
- 特殊分类或 AI/供应商辅助标签可用紫色。

### 背景与边框

```css
--app-bg-page: #f9fafb;
--app-bg-panel: #ffffff;
--app-bg-muted: #f3f4f6;
--app-bg-subtle: #fbfcff;
--app-border: #e5e7eb;
--app-border-soft: #f3f4f6;
--app-border-strong: #d1d5db;
```

规则：

- 页面背景使用浅灰。
- 卡片、弹窗、抽屉使用白底。
- 分割线尽量使用 `border-soft`，避免页面太硬。
- 只有输入框和重点容器使用较强边框。

### 间距

推荐 4px 基准：

```css
4 / 8 / 12 / 16 / 20 / 24 / 28 / 32
```

规则：

- 页面级 section 间距：`20px-24px`。
- 卡片内 padding：`20px-24px`。
- 表单字段之间：`12px-16px`。
- 按钮组间距：`8px-12px`。
- 表格行内左右 padding：`16px-20px`。

### 圆角与阴影

```css
--app-radius-sm: 6px;
--app-radius-md: 8px;
--app-radius-lg: 12px;
--app-radius-xl: 16px;
```

规则：

- 按钮、输入框：`8px`。
- 普通卡片：`12px`。
- 大弹窗、重点面板：`16px`。
- 不要混用过多圆角层级。

阴影规则：

- 普通卡片只用轻阴影。
- hover 卡片可以稍微增强。
- 弹窗、抽屉使用较强阴影。
- 不要让统计卡、普通表格卡有很重的投影。

## 页面布局规则

### 页面壳

页面应保持：

- 左侧主导航固定。
- 顶部栏固定，包含页面标题、空间切换、通知、用户。
- 主内容区域滚动。
- 页面内容不要贴边。

推荐：

```text
AppLayout
  AppSidebar
  AppHeader
  AppMain
```

### 设置类页面

系统设置、配置中心这类页面使用：

```text
左侧分类菜单 + 右侧内容区
```

规则：

- 左侧宽度约 `200px-240px`。
- 分类项包含图标、标题、辅助描述。
- 激活项使用浅蓝背景 + 主色文字。
- 右侧内容区只展示当前分类，不使用顶部 Tab 混杂。
- 未实现页面统一展示“页面建设中...”占位。

### 列表类页面

用例管理、缺陷管理、AI 生成记录使用：

```text
统计区 / 筛选区 / 表格区 / 分页区
```

规则：

- 筛选区和表格区之间要有明确间距。
- 表格可以作为卡片内表格，不要硬贴卡片边缘。
- 操作列宽度稳定。
- 固定列只保留轻边界，不使用厚重遮罩。
- 分页区和表格之间使用浅分割线。

### 工具型页面

接口自动化执行页属于工具型页面，应保持：

- 左侧目录树。
- 中间请求编辑区。
- 下方或右侧响应/执行结果区。
- 工具栏紧凑但不拥挤。
- 不做营销式大卡片布局。

## 组件规则

### Button

按钮分为：

- 主按钮：蓝底白字。
- 次按钮：白底灰边。
- 文字按钮：透明背景，主色文字。
- 危险按钮：红色语义。
- 图标按钮：固定尺寸，hover 有浅灰背景。

规则：

- 同一区域不要混用多套按钮高度。
- 普通按钮高度 `38px` 左右，小按钮 `32px`。
- loading 时按钮禁用或明确显示状态。
- 危险操作必须有确认。

### Table

规则：

- 表头背景浅灰。
- 表头字体 `12px-14px`，字重 `600`。
- 表格行高约 `54px`。
- 行 hover 使用极浅背景。
- 长文本省略，不撑破布局。
- 操作列固定时只显示轻边界，不要大阴影。
- 分页区高度稳定。

### Dialog / Drawer

规则：

- header、body、footer 分区清晰。
- header 高度约 `64px`。
- footer 使用浅分割线，操作按钮靠右。
- body 可滚动，header/footer 固定。
- 遮罩使用半透明深色，不要过黑。
- 提示消息不能被遮罩或弹窗层级挡住。

### Card

规则：

- 白底、浅边框、轻阴影。
- header 和 body 分割线使用浅色。
- hover 可以增强边框或阴影。
- 不要卡片套卡片。
- 页面 section 不要全部做成浮动卡片，只有重复项、统计项、配置项需要卡片化。

### Badge / Tag

规则：

- 状态必须有文字，不只靠颜色。
- P0/P1/P2 使用固定颜色规则。
- 供应商标签名称要统一，不同页面不要混用中文/英文。
- 状态胶囊使用浅底 + 深色文字。

### Empty / Loading / Error

规则：

- 页面建设中、暂无数据、正在加载、接口失败使用统一组件。
- 加载态不要先闪空状态。
- 错误态要给动作，例如“重试”“去配置”。
- 空状态不要过大，不要抢页面主视觉。

## AI 配置页规则

当前已验证的规则：

- 生成模型和评审模型使用双卡片并列。
- 每张卡片包含：角色标题、模型选择、测试连接、Temperature、Top-p、角色提示词、保存按钮。
- 默认进入页面时，卡片应在首屏内完整可见。
- 提示词默认展示内容预览，区域能展示多少展示多少，不出现内部滚动。
- 点击“展开编辑”后，卡片自然展开，textarea 显示完整内容并允许内部滚动。
- 保存按钮不能被压扁，需固定高度。

## AI 生成记录规则

- 输出板展示过程，不重复完整用例正文。
- 成功后输出板可以保留，便于回看。
- 表格展示最终可用用例或任务记录。
- 固定操作列不要遮挡正文。
- 查看详情抽屉中，结果和 AI 分析分 tab 展示。

## 配置中心规则

- 环境配置、参数配置、数据库连接统一使用卡片化列表。
- 统计卡在顶部，列表在下方。
- 新增/编辑弹窗视觉统一。
- 连接、测试、删除等操作使用轻量图标按钮或文字按钮。
- 配置中心左侧菜单不显示“配置分类”标题，直接展示分类。

## 系统设置规则

- 系统设置使用左侧设置分类。
- AI 连接池使用：
  - 页头说明。
  - 统计卡。
  - 连接卡片。
  - 支持供应商网格。
  - 两步式新增弹窗。
- 未实现分类显示建设中占位。
- AI 连接属于个人/平台配置时，应和公共配置中心保持边界清晰。

## 用例管理规则

- 左侧目录树和右侧列表保持双栏。
- 目录树使用浅蓝激活态。
- 右侧筛选区和表格区要有间距，不贴边。
- 表格区域可作为内缩卡片。
- 用例详情抽屉可以使用 tab：用例详情 / AI 分析。

## 代码组织建议

如果新项目重建，建议使用：

```text
src/
  app/
  pages/
  widgets/
  features/
  entities/
  shared/
```

推荐边界：

- `pages`：页面入口，只负责组合。
- `widgets`：页面级复合区域，例如 AI 连接池、用例表格、接口工作台。
- `features`：业务动作，例如新建、编辑、删除、测试连接、采纳用例。
- `entities`：稳定业务实体，例如 workspace、case、bug、ai-model。
- `shared/ui`：通用 UI 组件。
- `shared/api`：请求封装。
- `shared/styles`：token 和全局样式。

## Shared UI 建议

后续应优先封装：

```text
AppPage
AppSection
AppCard
AppTable
AppDialog
AppDrawer
AppButton
AppEmptyState
AppLoadingState
AppStatusBadge
AppProviderBadge
AppConfirm
```

规则：

- 页面不要到处裸写主 UI 库组件。
- 业务页面优先使用 shared/ui 封装。
- 页面 scoped CSS 只处理局部布局，不重新定义按钮、表格、弹窗视觉。

## 禁止项

- 不同时使用两套主 UI 组件库。
- 不在页面里随意写新的颜色、阴影、圆角体系。
- 不让大段 prompt 或长文本默认撑爆首屏。
- 不让表格固定列遮挡正文。
- 不让弹窗提示被遮罩挡住。
- 不在页面里重复实现状态标签、空状态、分页样式。
- 不把复杂页面继续堆成一个超大文件。

## 验收规则

推荐继续保留：

- `ui-acceptance-audit`：页面级横向溢出、主内容可见、内容尺寸检查。
- `ui-visual-round`：固定视口截图巡检。
- 视口至少覆盖：
  - `1366x768`
  - `1920x1080`

每次 UI 改造后至少检查：

- 样板页面是否被影响。
- 用例中心是否可用。
- 缺陷管理是否可用。
- 接口自动化执行页是否可用。
- 弹窗、抽屉、表格、空状态是否还统一。
